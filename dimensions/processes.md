# Processes

The team workflows around agent work, such as planning, review, integration and release, and how they change when agents write much of the code.

## Where the experts agree
- Once agents write much of the code, human verification sets the pace of delivery, not code generation. Teams should treat review capacity as a limited resource and aim AI at the review, test and validation queue rather than at producing more code. ([Thoughtworks: Verification is the bottleneck; spend human review by risk](../principles/thoughtworks/verification-is-the-bottleneck-spend-human-review-by-risk.md), [Addy Osmani: Review capacity is the bottleneck, so size work to it](../principles/osmani/review-capacity-is-the-bottleneck-so-size-work-to-it.md), [Simon Willison: Cheap code moves the bottleneck to validation](../principles/willison/cheap-code-moves-the-bottleneck-to-validation.md), [Charity Majors: Validation in production is the new bottleneck](../principles/majors/validation-in-production-is-the-new-bottleneck.md), [Anthropic engineering: Agents review first, humans approve by risk](../principles/anthropic/agents-review-first-humans-approve-by-risk.md), [DORA: Point AI at the delivery bottleneck, not at more code](../principles/dora/point-ai-at-the-delivery-bottleneck-not-at-more-code.md))
- Set review depth by risk. Run mechanical and agent checks first on everything. Put deep human review and deliberate friction on long-lived, critical or security-sensitive code, and judge low-stakes throwaway code mainly by whether it behaves correctly. The team still owns everything it ships. ([Thoughtworks: Verification is the bottleneck; spend human review by risk](../principles/thoughtworks/verification-is-the-bottleneck-spend-human-review-by-risk.md), [Gergely Orosz: Keep real human gates on agent changes, strongest on critical services](../principles/orosz/keep-real-human-gates-on-agent-changes-strongest-on-critical-services.md), [Anthropic engineering: Agents review first, humans approve by risk](../principles/anthropic/agents-review-first-humans-approve-by-risk.md), [Andrej Karpathy: A working demo is far from a reliable product](../principles/karpathy/a-working-demo-is-far-from-a-reliable-product.md), [Andrej Karpathy: Stay responsible for agent-written software](../principles/karpathy/stay-responsible-for-agent-written-software.md), [Simon Willison: Verify beyond line-by-line review, and earn trust in automated review](../principles/willison/verify-beyond-line-by-line-review-and-earn-trust-in-automated-review.md))
- Move the discussion of intent ahead of coding. Humans agree the design, plan and testable done criteria with the agent before it builds, then confirm at small checkpoints instead of one large review that ends up skimmed. ([Thoughtworks: Design and confirm intent in small staged steps](../principles/thoughtworks/design-and-confirm-intent-in-small-staged-steps.md), [Addy Osmani: Start from a precise, human-approved spec and record intent](../principles/osmani/start-from-a-precise-human-approved-spec-and-record-intent.md), [Anthropic engineering: Agree the plan and testable criteria before agents build](../principles/anthropic/agree-the-plan-and-testable-criteria-before-agents-build.md), [Gergely Orosz: Settle intent and design before agents build](../principles/orosz/settle-intent-and-design-before-agents-build.md))
- Keep the plan, spec, decisions and run logs behind agent work in version-controlled files next to the code. This lets reviewers see why a choice was made, lets humans step away and come back, and carries context from one session or run to the next. ([Gergely Orosz: Preserve the intent and decisions behind agent code](../principles/orosz/preserve-the-intent-and-decisions-behind-agent-code.md), [OpenAI engineering: Durable plans and run logs make delegated work inspectable](../principles/openai/durable-plans-and-run-logs-make-delegated-work-inspectable.md), [Addy Osmani: Start from a precise, human-approved spec and record intent](../principles/osmani/start-from-a-precise-human-approved-spec-and-record-intent.md))
- Add agents to existing collaborative practices such as pairing, mobbing, shared ownership and peer review. Do not replace those practices with solo human-plus-agent work, because that loses the daily interactions that build trust. ([Kent Beck: Keep humans working with humans](../principles/beck/keep-humans-working-with-humans.md), [Thoughtworks: Fold agents into proven collaborative practices and adopt them gradually](../principles/thoughtworks/fold-agents-into-proven-collaborative-practices-and-adopt-them-gradually.md))

## Where they disagree
- **Should human review of agent changes be kept as a lasting gate, or planned away in favour of layered agentic review?**
  - Human approval cannot keep up with agent speed. Add rounds of agent reviewers, judges and backstops, and plan to retire human review over time. ([Steve Yegge: Scale review with layers of agentic review](../principles/yegge/scale-review-with-layers-of-agentic-review.md))
  - Agents should do the first review pass, but an engaged, accountable human approves, with extra friction on critical services. Automation bias makes AI-only review risky. ([Gergely Orosz: Keep real human gates on agent changes, strongest on critical services](../principles/orosz/keep-real-human-gates-on-agent-changes-strongest-on-critical-services.md), [Anthropic engineering: Agents review first, humans approve by risk](../principles/anthropic/agents-review-first-humans-approve-by-risk.md), [Andrej Karpathy: Stay responsible for agent-written software](../principles/karpathy/stay-responsible-for-agent-written-software.md))
  - Relax human review only where the blast radius is small or an automated reviewer has earned trust through evidence. Watch for normalised deviance. ([Simon Willison: Verify beyond line-by-line review, and earn trust in automated review](../principles/willison/verify-beyond-line-by-line-review-and-earn-trust-in-automated-review.md))
  - Evidence to settle it: Compare escaped defects, security incidents and time to merge for matched changes, per risk tier, under agent-only layered review and under agent-first plus human approval.
  - Metric: Escaped defects and incidents per 100 merged changes, by risk tier and review mode, alongside median time to merge.
- **Should agent work start from a precise, approved upfront spec, or evolve from a shared living prototype in short cycles?**
  - Gate the work through spec, plan and tasks, with a human approving the spec before any code. Ambiguity multiplies across agents. ([Addy Osmani: Start from a precise, human-approved spec and record intent](../principles/osmani/start-from-a-precise-human-approved-spec-and-record-intent.md), [Thoughtworks: Design and confirm intent in small staged steps](../principles/thoughtworks/design-and-confirm-intent-in-small-staged-steps.md))
  - At agent speed, big upfront specs go stale. Work in the open around a prototype that evolves in short cycles, and use prototypes and PR discussion in place of long design documents and roadmaps. ([Steve Yegge: Build in the open around a living prototype](../principles/yegge/build-in-the-open-around-a-living-prototype.md), [Anthropic engineering: Agree the plan and testable criteria before agents build](../principles/anthropic/agree-the-plan-and-testable-criteria-before-agents-build.md))
  - Evidence to settle it: Run comparable features both ways, separating one-off work from long-lived services, and compare rework and idea-to-ship time.
  - Metric: Rework rate and idea-to-production lead time for spec-first versus prototype-first features, split by expected lifetime of the code.

## Measured
- DORA's survey data show larger changes are slower and less stable. Each 25% increase in AI adoption went with an estimated 7.2% drop in delivery stability. Holding small batch sizes and cheap rollback is therefore a deliberate discipline, not a default. ([DORA: Work in small batches, especially as AI speeds up change](../principles/dora/work-in-small-batches-especially-as-ai-speeds-up-change.md))
- Thoughtworks measured stories per iteration against a pre-AI baseline as teams adopted agents. It credits the gains to layering agents onto pairing, shared ownership and peer review, rolled out in phases, and reports a productivity dip before the gains arrived. ([Thoughtworks: Fold agents into proven collaborative practices and adopt them gradually](../principles/thoughtworks/fold-agents-into-proven-collaborative-practices-and-adopt-them-gradually.md))

## Open hypotheses
- Agent-heavy codebases quietly gather design drift and tech debt that humans no longer feel. Scheduled AI modularity reviews, team rituals and small nightly refactoring PRs can catch it before changes get expensive. ([Birgitta Böckeler: Catch design drift with periodic reviews and rituals](../principles/bockeler/catch-design-drift-with-periodic-reviews-and-rituals.md), [Gergely Orosz: Agents hide tech debt, so surface it and pay it down](../principles/orosz/agents-hide-tech-debt-so-surface-it-and-pay-it-down.md))
  - How to test it: Track files touched and tokens spent per change, plus workaround and TODO additions in agent PRs. Introduce periodic modularity reviews and nightly single-fix refactoring PRs on some services and compare the trends against services without them.
