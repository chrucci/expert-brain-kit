# Deterministic guardrails

Repeatable, non-model checks and inputs that constrain or validate agent work, such as tests, CI/CD, static analysis, specifications and requirements from the business.

## Where the experts agree
- Rules that must always or never hold belong in deterministic gates such as hooks, permissions, lint rules, tests and fail-closed tool limits, not in prompt instructions. Instructions only make good behaviour more likely, and agents break them under pressure. ([Thoughtworks: Enforce agent work with deterministic sensors in the loop](../principles/thoughtworks/enforce-agent-work-with-deterministic-sensors-in-the-loop.md), [Anthropic engineering: Move rules out of prompts and into deterministic gates](../principles/anthropic/move-rules-out-of-prompts-and-into-deterministic-gates.md), [Steve Yegge: Enforce critical rules mechanically, and curate the fences](../principles/yegge/enforce-critical-rules-mechanically-and-curate-the-fences.md), [Birgitta Böckeler: Verify outcomes instead of prescribing the agent's process](../principles/bockeler/verify-outcomes-instead-of-prescribing-the-agent-s-process.md))
- Work is done when an independent, machine-checkable finish line passes, not when the agent says so. Each task should name the check (tests, build, lint, a script that calls the endpoint) and run in an environment where the agent can execute it. Agents should not merge their own work. A gated queue should land it. ([Addy Osmani: Deterministic checks, not the agent, decide when work is done](../principles/osmani/deterministic-checks-not-the-agent-decide-when-work-is-done.md), [Anthropic engineering: Done means a check the agent can run](../principles/anthropic/done-means-a-check-the-agent-can-run.md), [OpenAI engineering: A checkable definition of done, proven by fast execution](../principles/openai/a-checkable-definition-of-done-proven-by-fast-execution.md), [Steve Yegge: Agents never land their own work: a gated merge queue decides](../principles/yegge/agents-never-land-their-own-work-a-gated-merge-queue-decides.md), [Simon Willison: Agents must run their work and show evidence it works](../principles/willison/agents-must-run-their-work-and-show-evidence-it-works.md))
- Cheap, fast checks wired into the agent loop let agents correct themselves before a human looks. Keep the inner loop to about a minute, write lint messages that tell the agent how to fix the problem, and feed production errors back into the loop. ([Birgitta Böckeler: Pair guides with fast, self-correcting sensors](../principles/bockeler/pair-guides-with-fast-self-correcting-sensors.md), [Thoughtworks: Enforce agent work with deterministic sensors in the loop](../principles/thoughtworks/enforce-agent-work-with-deterministic-sensors-in-the-loop.md), [Gergely Orosz: Close the loop with mechanical validation](../principles/orosz/close-the-loop-with-mechanical-validation.md), [OpenAI engineering: A checkable definition of done, proven by fast execution](../principles/openai/a-checkable-definition-of-done-proven-by-fast-execution.md), [OpenAI engineering: Enforce architecture and taste mechanically and continuously](../principles/openai/enforce-architecture-and-taste-mechanically-and-continuously.md))
- Treat every repeated agent mistake or repeated review comment as a signal to add a permanent check, such as a lint rule, test, hook or tool, rather than fixing the diff by hand. Over time the harness, not human vigilance, keeps agents on track. ([Mitchell Hashimoto: Turn every agent mistake into a permanent guardrail](../principles/hashimoto/turn-every-agent-mistake-into-a-permanent-guardrail.md), [Addy Osmani: Grow the harness from real failures and prune it](../principles/osmani/grow-the-harness-from-real-failures-and-prune-it.md), [Anthropic engineering: Move rules out of prompts and into deterministic gates](../principles/anthropic/move-rules-out-of-prompts-and-into-deterministic-gates.md), [Steve Yegge: Enforce critical rules mechanically, and curate the fences](../principles/yegge/enforce-critical-rules-mechanically-and-curate-the-fences.md))
- A green suite the agent wrote for itself does not prove the behaviour is right. Humans should own the behavioural specification and contracts in checkable form, and mutation testing or execution evidence should show that the tests actually catch broken behaviour. ([Birgitta Böckeler: Agent-written tests are not proof of correctness](../principles/bockeler/agent-written-tests-are-not-proof-of-correctness.md), [Robert C. Martin: Humans own the behavioural specification](../principles/unclebob/humans-own-the-behavioural-specification.md), [Kent Beck: Make expectations explicit and let the agent observe real behaviour](../principles/beck/make-expectations-explicit-and-let-the-agent-observe-real-behaviour.md), [Simon Willison: Agents must run their work and show evidence it works](../principles/willison/agents-must-run-their-work-and-show-evidence-it-works.md))
- Pinning existing behaviour first makes large agent changes safe. Characterization tests, conformance suites, capture and replay, and a trusted reference implementation let agents change legacy services or rewrite them, with shadow runs on real traffic as the final check. ([Simon Willison: Conformance suites make agent-driven ports and rewrites viable](../principles/willison/conformance-suites-make-agent-driven-ports-and-rewrites-viable.md), [Charity Majors: Encode the team's knowledge into the system](../principles/majors/encode-the-team-s-knowledge-into-the-system.md), [Addy Osmani: Deterministic checks, not the agent, decide when work is done](../principles/osmani/deterministic-checks-not-the-agent-decide-when-work-is-done.md))

## Where they disagree
- **Should teams tell agents to work test-first, or only verify the outcome?**
  - Yes. Agents should run the suite first and work in small red/green steps, keeping only green changes, because without tests they delete assertions or drift. ([Simon Willison: Automated tests are mandatory, and agents work test-first](../principles/willison/automated-tests-are-mandatory-and-agents-work-test-first.md), [Kent Beck: Rein in the agent with small, test-gated steps](../principles/beck/rein-in-the-agent-with-small-test-gated-steps.md))
  - No. Prescribing TDD added cost without measurable quality gains, and an agent confirming its own red test proves little without a human checkpoint. Put the effort into outcome checks and hooks. ([Birgitta Böckeler: Verify outcomes instead of prescribing the agent's process](../principles/bockeler/verify-outcomes-instead-of-prescribing-the-agent-s-process.md), [Birgitta Böckeler: Agent-written tests are not proof of correctness](../principles/bockeler/agent-written-tests-are-not-proof-of-correctness.md))
  - Evidence to settle it: Run the same set of service tasks with and without test-first instructions, holding the outcome gates fixed, and compare blind quality rankings, mutation scores, escaped defects and tokens per task.
  - Metric: Mutation score and escaped defects per task, alongside tokens per task, for test-first versus outcome-only runs.
- **Once a gate is added, should it ever be loosened or removed?**
  - Gates only tighten. Quality should rise steadily, and no gate comes back off, though redundant harness pieces can be pruned. ([Addy Osmani: Grow the harness from real failures and prune it](../principles/osmani/grow-the-harness-from-real-failures-and-prune-it.md))
  - Thresholds should be relaxed as models improve, and the fence set should be kept small and curated, with a named human approving new fences. ([Robert C. Martin: Agree on shared deterministic gates and loosen thresholds only as agents improve](../principles/unclebob/agree-on-shared-deterministic-gates-and-loosen-thresholds-only-as-agents-improve.md), [Steve Yegge: Enforce critical rules mechanically, and curate the fences](../principles/yegge/enforce-critical-rules-mechanically-and-curate-the-fences.md))
  - Evidence to settle it: Loosen or remove individual gates one at a time in a controlled way and see whether escaped defects or rule re-violations rise.
  - Metric: Escaped defects and re-violations of each rule before and after each gate change, plus each gate's unique catch rate (problems no other stage caught).

## Measured
- METR found that fully autonomous agents often implement the core functionality of real repository issues correctly but leave out documentation, fail lint and style rules, and skip key unit or integration tests. Automated checks are what decide whether the work is actually complete. ([METR: Use deterministic gates to finish agent work](../principles/metr/use-deterministic-gates-to-finish-agent-work.md))
- Böckeler compared agent runs with and without a prescribed TDD workflow. The prescribed process added cost without measurable quality gains, which supports enforcing what matters through hooks and outcome checks. ([Birgitta Böckeler: Verify outcomes instead of prescribing the agent's process](../principles/bockeler/verify-outcomes-instead-of-prescribing-the-agent-s-process.md))

## Open hypotheses
- Green gates on agent output measure test strength, not design quality. Coverage and complexity gates can push agents to split code into many tiny, less readable functions, and coverage-driven generated tests add little. ([Robert C. Martin: Quality gates buy test strength, not design](../principles/unclebob/quality-gates-buy-test-strength-not-design.md), [Unmesh Joshi: Coverage-driven generated tests are not a guardrail](../principles/joshi/coverage-driven-generated-tests-are-not-a-guardrail.md))
  - How to test it: Have agents regenerate the same feature several times under the gates. Compare coverage, mutation score, function count, reviewer-rated readability and structural differences that the acceptance suite does not detect.
