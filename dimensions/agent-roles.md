# Roles for agents

What agents are given to do, how much autonomy they get, and where they must stop and hand back to a human.

## Where the experts agree
- Agent autonomy is earned, not granted. Start with tight permissions and sandboxes, set autonomy per task type based on risk, blast radius and how strong the automated checks are, and widen it only as evidence builds up. Tighten it again when trust is lost. ([Thoughtworks: Widen agent autonomy narrowly and with evidence](../principles/thoughtworks/widen-agent-autonomy-narrowly-and-with-evidence.md), [Addy Osmani: Let verification and risk set agent autonomy](../principles/osmani/let-verification-and-risk-set-agent-autonomy.md), [Charity Majors: Earn agent autonomy over merging with guardrails and evidence](../principles/majors/earn-agent-autonomy-over-merging-with-guardrails-and-evidence.md), [OpenAI engineering: Earn agent autonomy gradually within fixed boundaries](../principles/openai/earn-agent-autonomy-gradually-within-fixed-boundaries.md), [Andrej Karpathy: Turn up autonomy gradually with an autonomy slider](../principles/karpathy/turn-up-autonomy-gradually-with-an-autonomy-slider.md))
- The agent that builds a change should not be the one that judges it. Agents overrate their own work and their summaries can hide shortcuts, so checking belongs to separate, fresh-context reviewer or verifier agents with a critical brief, and humans check the actual diffs. ([Kent Beck: Verify what the agent did, not what it claims](../principles/beck/verify-what-the-agent-did-not-what-it-claims.md), [Addy Osmani: Separate, narrow agent roles with a human orchestrating](../principles/osmani/separate-narrow-agent-roles-with-a-human-orchestrating.md), [Anthropic engineering: Independent, human-calibrated agent reviewers](../principles/anthropic/independent-human-calibrated-agent-reviewers.md), [Thoughtworks: Prompt agents to audit critically before acting](../principles/thoughtworks/prompt-agents-to-audit-critically-before-acting.md))
- Give agents narrow, single-purpose roles with least-privilege tools and a clear statement of what each role may change, rather than one broadly permissioned agent. ([Addy Osmani: Separate, narrow agent roles with a human orchestrating](../principles/osmani/separate-narrow-agent-roles-with-a-human-orchestrating.md), [Robert C. Martin: Pipeline of specialised agent roles with exclusive ownership](../principles/unclebob/pipeline-of-specialised-agent-roles-with-exclusive-ownership.md), [Steve Yegge: Separate worker, supervisor and merger roles; supervisors are a safety net](../principles/yegge/separate-worker-supervisor-and-merger-roles-supervisors-are-a-safety-net.md), [Thoughtworks: Widen agent autonomy narrowly and with evidence](../principles/thoughtworks/widen-agent-autonomy-narrowly-and-with-evidence.md))
- Make the hand-back points explicit. Bound each run with a human-approved plan for larger work and clear stop conditions, have agents escalate or file issues instead of bypassing gates or drifting out of scope, and keep hard stops where a human signs off. ([OpenAI engineering: Plan, size and bound each agent run](../principles/openai/plan-size-and-bound-each-agent-run.md), [Steve Yegge: Agents stay in scope and escalate instead of bypassing](../principles/yegge/agents-stay-in-scope-and-escalate-instead-of-bypassing.md), [Thoughtworks: Widen agent autonomy narrowly and with evidence](../principles/thoughtworks/widen-agent-autonomy-narrowly-and-with-evidence.md))

## Where they disagree
- **Should checking stages gate every piece of work, or stay off the routine completion path?**
  - Every change passes through a fixed chain of role stages. No stage is skipped, and each one is accountable for one concern. ([Robert C. Martin: Pipeline of specialised agent roles with exclusive ownership](../principles/unclebob/pipeline-of-specialised-agent-roles-with-exclusive-ownership.md))
  - Workers own their task through to completion, and supervisors act as a safety net that does not gate completion. A single gatekeeper turns parallel work back into serial work. ([Steve Yegge: Separate worker, supervisor and merger roles; supervisors are a safety net](../principles/yegge/separate-worker-supervisor-and-merger-roles-supervisors-are-a-safety-net.md))
  - Evidence to settle it: Run the same backlog through a full gated pipeline and through a worker-owned flow with supervisors on the side, at increasing numbers of parallel workers, and compare quality against throughput.
  - Metric: Escaped defects per change and median completion latency, plotted against the number of parallel workers.
- **Who should orchestrate the agents: a human, or other agents?**
  - A human or a fixed command orchestrates, agents do not call each other, and a human chooses which work agents implement. ([Addy Osmani: Separate, narrow agent roles with a human orchestrating](../principles/osmani/separate-narrow-agent-roles-with-a-human-orchestrating.md), [Mitchell Hashimoto: Read-only triage agents, with a human choosing what agents implement](../principles/hashimoto/read-only-triage-agents-with-a-human-choosing-what-agents-implement.md))
  - Agent supervisors and pipelines coordinate the work themselves, detecting stalls, recovering work and forwarding between roles, and humans step in at gates and escalations. ([Steve Yegge: Separate worker, supervisor and merger roles; supervisors are a safety net](../principles/yegge/separate-worker-supervisor-and-merger-roles-supervisors-are-a-safety-net.md), [Robert C. Martin: Pipeline of specialised agent roles with exclusive ownership](../principles/unclebob/pipeline-of-specialised-agent-roles-with-exclusive-ownership.md))
  - Evidence to settle it: Compare human-orchestrated and agent-orchestrated runs on similar task types, and measure both outcomes and the human attention each one uses.
  - Metric: Landed changes per human hour of attention, alongside rework and out-of-scope change rates.

## Measured
- Different AI reviewers rarely catch the same bugs, and authoring agents rate their own work too kindly. This supports using separate, differently built reviewer agents. ([Addy Osmani: Separate, narrow agent roles with a human orchestrating](../principles/osmani/separate-narrow-agent-roles-with-a-human-orchestrating.md))
- Agents reliably complete tedious, well-bounded and trial-and-error work such as long refactors, toolchain fixes, merge conflicts, release notes and autoresearch loops, provided each result is gated by tests and human review. The evidence tracks completion and landing rates and benchmark gains per run. ([Simon Willison: Delegate tedious, well-bounded and trial-and-error work to agents](../principles/willison/delegate-tedious-well-bounded-and-trial-and-error-work-to-agents.md))
- In a controlled study, AI assistance slowed developers down more on tasks they already knew well, and was consistent with speedups on unfamiliar codebases and small greenfield projects. The result comes from one setting and should not be generalised without checking. ([METR: Expect AI to help most where you know least](../principles/metr/expect-ai-to-help-most-where-you-know-least.md))

## Open hypotheses
- Agent implementation success rises if read-only triage agents scan the backlog and a human picks the issues an agent will almost certainly solve, then runs them one at a time. ([Mitchell Hashimoto: Read-only triage agents, with a human choosing what agents implement](../principles/hashimoto/read-only-triage-agents-with-a-human-choosing-what-agents-implement.md))
  - How to test it: Over a few weeks, split agent-implemented issues into human-picked from triage reports and assigned without that filter, and compare merge rate and rework.
- Letting the model decide which context to load is what makes unsupervised runs possible, but it only works where that context reliably gets loaded. Where it does not, a human trigger or a hook is the safer choice. ([Birgitta Böckeler: Choose deliberately who triggers context](../principles/bockeler/choose-deliberately-who-triggers-context.md))
  - How to test it: Log, for each piece of context the model loads on its own, how often it is loaded on tasks where it is relevant. Move pieces with low load rates to hooks or human triggers and compare outcomes.
