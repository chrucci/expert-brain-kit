# Roles for agents

What agents are given to do, how much autonomy they get, and where they must stop and hand back to a human.

## Where the experts agree
- Autonomy is earned rather than switched on. Start agents with narrow permissions and tight approval, set autonomy per task by risk, blast radius and how strong the automated checks are, and widen it step by step only as evidence builds up. Tighten it again when things go wrong. ([Thoughtworks: Widen agent autonomy narrowly and with evidence](../principles/thoughtworks/widen-agent-autonomy-narrowly-and-with-evidence.md), [Addy Osmani: Let verification and risk set agent autonomy](../principles/osmani/let-verification-and-risk-set-agent-autonomy.md), [Charity Majors: Earn agent autonomy over merging with guardrails and evidence](../principles/majors/earn-agent-autonomy-over-merging-with-guardrails-and-evidence.md), [OpenAI engineering: Earn agent autonomy gradually within fixed boundaries](../principles/openai/earn-agent-autonomy-gradually-within-fixed-boundaries.md))
- The agent that builds a change should not be the one that judges it. Agents overrate their own work and their summaries can hide shortcuts, so checking belongs to separate, fresh-context reviewer or verifier agents with a critical brief, backed by human inspection of the real diffs. ([Kent Beck: Verify what the agent did, not what it claims](../principles/beck/verify-what-the-agent-did-not-what-it-claims.md), [Addy Osmani: Separate, narrow agent roles with a human orchestrating](../principles/osmani/separate-narrow-agent-roles-with-a-human-orchestrating.md), [Anthropic engineering: Independent, human-calibrated agent reviewers](../principles/anthropic/independent-human-calibrated-agent-reviewers.md), [Thoughtworks: Prompt agents to audit critically before acting](../principles/thoughtworks/prompt-agents-to-audit-critically-before-acting.md))
- Every agent role needs explicit stop points where it hands back to a human: a human-approved plan before large work, stop conditions for loops, gates for sign-off, and escalation instead of skipping a failed step or fixing things outside scope. ([OpenAI engineering: Plan, size and bound each agent run](../principles/openai/plan-size-and-bound-each-agent-run.md), [Steve Yegge: Agents stay in scope and escalate instead of bypassing](../principles/yegge/agents-stay-in-scope-and-escalate-instead-of-bypassing.md), [Thoughtworks: Widen agent autonomy narrowly and with evidence](../principles/thoughtworks/widen-agent-autonomy-narrowly-and-with-evidence.md))
- Good jobs to give agents are bounded, tedious or watchful work that people put off: refactors, toolchain trial and error, release notes, adding instrumentation, staged rollouts and long-term watching of risky changes. Tests, review or production signals still check the results. ([Simon Willison: Delegate tedious, well-bounded and trial-and-error work to agents](../principles/willison/delegate-tedious-well-bounded-and-trial-and-error-work-to-agents.md), [Charity Majors: Agents instrument, roll out and watch changes](../principles/majors/agents-instrument-roll-out-and-watch-changes.md))

## Where they disagree
- **Can an agent check its own work, or must another agent or a human always do the checking?**
  - Self-verification is critical infrastructure. An agent that can check its own output keeps going until the work is done, which takes the human out of the slowest part of the loop. ([Lauren Tan: Agents verify their own work so humans stop being the bottleneck](../principles/tan/agents-verify-their-own-work-so-humans-stop-being-the-bottleneck.md))
  - Authors grade themselves too kindly, so verification must come from separate agents with their own context, tuned by humans. ([Addy Osmani: Separate, narrow agent roles with a human orchestrating](../principles/osmani/separate-narrow-agent-roles-with-a-human-orchestrating.md), [Anthropic engineering: Independent, human-calibrated agent reviewers](../principles/anthropic/independent-human-calibrated-agent-reviewers.md), [Kent Beck: Verify what the agent did, not what it claims](../principles/beck/verify-what-the-agent-did-not-what-it-claims.md))
  - Evidence to settle it: A side-by-side trial on the same kinds of task: the authoring agent self-verifies in one arm, and a separate verifier agent checks in the other. Compare defects that escape and total cycle time.
  - Metric: Escaped defects per merged PR and agent idle time waiting for review, split by self-verified versus independently verified changes.
- **Who coordinates multi-agent work: a human or a fixed pipeline, or agents supervising each other?**
  - A human or a fixed command orchestrates. Agents do not call each other, and every stage in a fixed role chain always runs. ([Addy Osmani: Separate, narrow agent roles with a human orchestrating](../principles/osmani/separate-narrow-agent-roles-with-a-human-orchestrating.md), [Robert C. Martin: Pipeline of specialised agent roles with exclusive ownership](../principles/unclebob/pipeline-of-specialised-agent-roles-with-exclusive-ownership.md))
  - Workers own their task through to completion, and agent supervisors act only as a safety net that stays off the completion path, so that parallel work does not turn back into serial work. ([Steve Yegge: Separate worker, supervisor and merger roles; supervisors are a safety net](../principles/yegge/separate-worker-supervisor-and-merger-roles-supervisors-are-a-safety-net.md))
  - Evidence to settle it: Run both coordination styles while raising the number of parallel workers, and see where throughput stops scaling and where defects or lost work rise.
  - Metric: Completion latency and escaped defects as the count of parallel workers grows, plus work lost per stall or crash incident.

## Measured
- METR compared task completion times with AI allowed and with AI disallowed. Developers with high prior exposure to a task were slowed down by AI. The results are consistent with large speedups on small greenfield projects and in unfamiliar codebases. Agent roles should therefore be set by setting, not applied uniformly. ([METR: Expect AI to help most where you know least](../principles/metr/expect-ai-to-help-most-where-you-know-least.md))
- When AI reviewers built in different ways were run on the same changes, they rarely caught the same bugs. This supports using several separate reviewer roles rather than one. ([Addy Osmani: Separate, narrow agent roles with a human orchestrating](../principles/osmani/separate-narrow-agent-roles-with-a-human-orchestrating.md))

## Open hypotheses
- If a human picks, from read-only triage reports, the issues an agent will almost certainly solve well, agents land more of the work they are given than if issues are assigned without that filter. ([Mitchell Hashimoto: Read-only triage agents, with a human choosing what agents implement](../principles/hashimoto/read-only-triage-agents-with-a-human-choosing-what-agents-implement.md))
  - How to test it: For a month, send half of the agent-eligible issues through human selection from triage reports and assign the other half directly. Compare landing rate and rework.
- Agents running unsupervised can't be relied on to load the context they need on their own, so tasks where context is model-loaded need lower autonomy than tasks where a hook or a human triggers it. ([Birgitta Böckeler: Choose deliberately who triggers context](../principles/bockeler/choose-deliberately-who-triggers-context.md), [Andrej Karpathy: Turn up autonomy gradually with an autonomy slider](../principles/karpathy/turn-up-autonomy-gradually-with-an-autonomy-slider.md))
  - How to test it: For each piece of context the model is left to load, log how often it actually gets loaded on the tasks where it is relevant. Compare the intervention rate with runs where hooks load the same context.
