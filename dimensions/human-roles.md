# Roles for humans

What the humans on a team are responsible for and own when agents do much of the work.

## Where the experts agree
- Humans own intent, design, architecture and taste. Agents do the implementation. People decide what to build and whether it belongs in the product, and agents work out how to build it. ([Andrej Karpathy: The human owns the spec, design and taste](../principles/karpathy/the-human-owns-the-spec-design-and-taste.md), [Thoughtworks: Experienced humans own design quality, intent and strategy](../principles/thoughtworks/experienced-humans-own-design-quality-intent-and-strategy.md), [Addy Osmani: Humans own the outer loop: intent, judgment and the ship decision](../principles/osmani/humans-own-the-outer-loop-intent-judgment-and-the-ship-decision.md), [Simon Willison: Humans own what gets built](../principles/willison/humans-own-what-gets-built.md), [Anthropic engineering: Humans own the what, agents own the how](../principles/anthropic/humans-own-the-what-agents-own-the-how.md), [Steve Yegge: Humans keep judgment, taste and the final say](../principles/yegge/humans-keep-judgment-taste-and-the-final-say.md))
- Each piece of agent work needs a named human owner who makes the ship decision and answers for the result. An agent cannot be held responsible, so whoever directs or merges the work owns it. ([Addy Osmani: Humans own the outer loop: intent, judgment and the ship decision](../principles/osmani/humans-own-the-outer-loop-intent-judgment-and-the-ship-decision.md), [Gergely Orosz: Engineers own areas, architecture and the release decision](../principles/orosz/engineers-own-areas-architecture-and-the-release-decision.md), [Simon Willison: A human vouches for agent output before others depend on it](../principles/willison/a-human-vouches-for-agent-output-before-others-depend-on-it.md), [Anthropic engineering: Humans own the what, agents own the how](../principles/anthropic/humans-own-the-what-agents-own-the-how.md))
- Humans steer through the harness, not by fixing outputs one at a time. When an agent makes the same mistake twice, the human adds a lasting guide, test, lint or doc to the repository, and a named person keeps that loop up to date. ([Birgitta Böckeler: Humans steer by improving the harness](../principles/bockeler/humans-steer-by-improving-the-harness.md), [Thoughtworks: Humans on the loop: fix the harness, not the artefact](../principles/thoughtworks/humans-on-the-loop-fix-the-harness-not-the-artefact.md), [OpenAI engineering: Engineers own the harness and turn each agent failure into a lasting fix](../principles/openai/engineers-own-the-harness-and-turn-each-agent-failure-into-a-lasting-fix.md))
- Humans have to keep the system understandable over time. Agent speed lets complexity and cognitive debt grow faster than the team can follow, so people must keep understanding the critical parts well enough to keep steering them. ([Kent Beck: A person must own the system's long-term health](../principles/beck/a-person-must-own-the-system-s-long-term-health.md), [Simon Willison: Pay down cognitive debt on agent-written code](../principles/willison/pay-down-cognitive-debt-on-agent-written-code.md), [Unmesh Joshi: Humans keep writing code to discover design](../principles/joshi/humans-keep-writing-code-to-discover-design.md))

## Where they disagree
- **Should humans review agent code closely, or check above the code level and leave line-level validation to machines?**
  - Humans should review and understand agent code as it arrives and vouch for it before others depend on it. Faster reviews may be a sign of over-trust. ([Martin Fowler: Humans own and evaluate what agents build](../principles/fowler/humans-own-and-evaluate-what-agents-build.md), [Birgitta Böckeler: Keep comprehension in the moment](../principles/bockeler/keep-comprehension-in-the-moment.md), [Simon Willison: A human vouches for agent output before others depend on it](../principles/willison/a-human-vouches-for-agent-output-before-others-depend-on-it.md), [DORA: Trust but verify AI output](../principles/dora/trust-but-verify-ai-output.md))
  - Line-by-line review makes humans the bottleneck, and humans are poor at repetitive validation. Automate the checks, review a sample, and spend human attention on design, product fit and architecture. ([Charity Majors: Humans judge what to build; machines are the quality gate](../principles/majors/humans-judge-what-to-build-machines-are-the-quality-gate.md), [OpenAI engineering: Human attention, not code generation, is the bottleneck](../principles/openai/human-attention-not-code-generation-is-the-bottleneck.md), [Thoughtworks: Humans on the loop: fix the harness, not the artefact](../principles/thoughtworks/humans-on-the-loop-fix-the-harness-not-the-artefact.md), [Robert C. Martin: Humans are responsible just above the code level](../principles/unclebob/humans-are-responsible-just-above-the-code-level.md))
  - Evidence to settle it: Run comparable services under each review policy for a quarter, with strong automated gates in both. Compare escaped defects, rework and lead time.
  - Metric: Escaped defects and change failure rate per merged agent change, alongside time to merge, split by review policy (full line review vs. sampled or design-level review).
- **Should engineers keep writing and reshaping code, or move to directing crews of parallel agents?**
  - Developers should keep actively writing and refactoring code, especially while the design is still being worked out. Review alone does not make people think through where responsibilities belong. ([Unmesh Joshi: Humans keep writing code to discover design](../principles/joshi/humans-keep-writing-code-to-discover-design.md), [Kent Beck: A person must own the system's long-term health](../principles/beck/a-person-must-own-the-system-s-long-term-health.md))
  - The human job becomes leadership. An engineer owns an area, directs several agents in parallel, and paces their output to what people can check. ([Gergely Orosz: Engineers own areas, architecture and the release decision](../principles/orosz/engineers-own-areas-architecture-and-the-release-decision.md), [Steve Yegge: Humans lead and govern agent crews](../principles/yegge/humans-lead-and-govern-agent-crews.md))
  - Evidence to settle it: Compare modules whose structure humans wrote or refactored with modules built entirely by directed agent crews. Look at how readable and changeable they are 6 to 12 months later.
  - Metric: Follow-on change lead time and the share of agent-built structure later reworked or deleted, by module authorship style.

## Measured
- Anthropic measured who makes decisions in agentic coding sessions. People made about 70% of planning decisions but only about 20% of execution decisions, so in practice humans decide what to build and agents decide how. ([Anthropic engineering: Humans own the what, agents own the how](../principles/anthropic/humans-own-the-what-agents-own-the-how.md))
- Anthropic instrumented real sessions and found that experienced users let agents run more on their own and step in when needed. Effective oversight came from being able to see what the agent was doing and intervene in time, not from approving every action. ([Anthropic engineering: Oversee by monitoring and clear handback points](../principles/anthropic/oversee-by-monitoring-and-clear-handback-points.md))
- At OpenAI, weekly PR volume more than doubled after agents were adopted. Human review became the constraint, which suggests synchronous human attention is now the scarce resource. ([OpenAI engineering: Human attention, not code generation, is the bottleneck](../principles/openai/human-attention-not-code-generation-is-the-bottleneck.md))

## Open hypotheses
- Keeping an agent busy on background work, with notifications off so the human decides when to check in, raises throughput without costing focus. ([Mitchell Hashimoto: An agent always runs in the background, on the human's schedule](../principles/hashimoto/an-agent-always-runs-in-the-background-on-the-human-s-schedule.md))
  - How to test it: Have engineers alternate weeks with agent notifications on and off. Compare uninterrupted focus time, merged changes and the share of hours with an agent task running.
- Agent-generated changes cause fewer production problems when the engineers who support the system on call set the rules for shipping them. ([Charity Majors: Owning engineers set the shipping conditions](../principles/majors/owning-engineers-set-the-shipping-conditions.md), [Kent Beck: Humans keep the caring and the accountability](../principles/beck/humans-keep-the-caring-and-the-accountability.md))
  - How to test it: For each service, record whether its on-call owners signed off on the rules for AI-generated changes. Compare change failure rate and incident count for agent changes between services where they did and services where they did not.
