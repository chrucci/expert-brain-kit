# Tools

Which coding agents, models and supporting tools a team uses, and how it chooses and combines them.

## Where the experts agree
- Split work across model tiers by difficulty. A strong model plans, designs and handles hard reasoning. Cheaper or smaller models run routine, well-scoped tasks. This cuts cost without lowering quality. ([Addy Osmani: Route work to models by difficulty](../principles/osmani/route-work-to-models-by-difficulty.md), [Steve Yegge: Route work to the cheapest capable model; the strong model designs and reviews](../principles/yegge/route-work-to-the-cheapest-capable-model-the-strong-model-designs-and-reviews.md), [Birgitta Böckeler: Plan with strong models, execute narrow tasks with weaker ones](../principles/bockeler/plan-with-strong-models-execute-narrow-tasks-with-weaker-ones.md), [Anthropic engineering: Match model and effort to scope, checkability and supervision](../principles/anthropic/match-model-and-effort-to-scope-checkability-and-supervision.md))
- Choose agents and models with evals on your own representative tasks, not by reputation. Rerun those evals whenever models or setups change, because what a model can do is uneven and comes with no manual. ([Andrej Karpathy: Map a model's jagged capabilities empirically](../principles/karpathy/map-a-model-s-jagged-capabilities-empirically.md), [Thoughtworks: Choose a small agent tool set deliberately, by evals and task scope](../principles/thoughtworks/choose-a-small-agent-tool-set-deliberately-by-evals-and-task-scope.md), [Steve Yegge: Route work to the cheapest capable model; the strong model designs and reviews](../principles/yegge/route-work-to-the-cheapest-capable-model-the-strong-model-designs-and-reviews.md), [Anthropic engineering: Match model and effort to scope, checkability and supervision](../principles/anthropic/match-model-and-effort-to-scope-checkability-and-supervision.md))
- Agents need an environment they can read and that limits what they can do: constrained architecture and strong typing, CLIs that explain themselves, and telemetry agents can query precisely. Treat these as tooling investments. ([Birgitta Böckeler: Choose stacks and architecture for harnessability](../principles/bockeler/choose-stacks-and-architecture-for-harnessability.md), [Simon Willison: Build tools agents can learn from their own help](../principles/willison/build-tools-agents-can-learn-from-their-own-help.md), [Charity Majors: Keep telemetry wide and high-cardinality](../principles/majors/keep-telemetry-wide-and-high-cardinality.md))

## Where they disagree
- **Should code review go to a cheap model or the strongest one?**
  - Code review and CI checks are routine work and can go to a small, cheap model. ([Addy Osmani: Route work to models by difficulty](../principles/osmani/route-work-to-models-by-difficulty.md))
  - Review, like security, is full of edge cases and belongs with the strongest model at high effort. ([Anthropic engineering: Match model and effort to scope, checkability and supervision](../principles/anthropic/match-model-and-effort-to-scope-checkability-and-supervision.md), [Steve Yegge: Route work to the cheapest capable model; the strong model designs and reviews](../principles/yegge/route-work-to-the-cheapest-capable-model-the-strong-model-designs-and-reviews.md))
  - Evidence to settle it: Seed a set of changes with known defects and run reviews with both model tiers. Compare how many defects each catches and what each costs.
  - Metric: Seeded-defect catch rate and escaped defects per review, plus token cost per review, by model tier.
- **Should a team keep a small tool set or combine many models, sub-agents and tools?**
  - Keep the stack small so people build mastery and avoid switching contexts. ([Thoughtworks: Choose a small agent tool set deliberately, by evals and task scope](../principles/thoughtworks/choose-a-small-agent-tool-set-deliberately-by-evals-and-task-scope.md))
  - Combine many models, sub-agents and tools, routing each task to the cheapest one that can do it, and treat managing that mix as core engineering work. ([Steve Yegge: Route work to the cheapest capable model; the strong model designs and reviews](../principles/yegge/route-work-to-the-cheapest-capable-model-the-strong-model-designs-and-reviews.md))
  - Evidence to settle it: Compare teams or periods with few tools against those with heavy multi-model routing, looking at cost, throughput and the time spent managing tools.
  - Metric: AI tools in active use per engineer, set against cost per completed task, rework rate and hours spent on tool and routing upkeep.
- **Should what agents handle well drive technology choices?**
  - Yes. Pick stacks and structures that are easy to harness, such as strong typing, enforced boundaries and structural tests. ([Birgitta Böckeler: Choose stacks and architecture for harnessability](../principles/bockeler/choose-stacks-and-architecture-for-harnessability.md))
  - Mostly no. With good help output, docs and skills, agents can work with new or private technology, so choose the stack on merit. ([Simon Willison: Build tools agents can learn from their own help](../principles/willison/build-tools-agents-can-learn-from-their-own-help.md))
  - Evidence to settle it: Run the same agent tasks on a strongly typed, tightly constrained stack and on a looser or less familiar stack that has good docs and skills.
  - Metric: First-attempt task success, rework and architectural-rule violations per stack.

## Measured
- Anthropic compared model tiers and effort levels across task types. Cheaper models did best on tasks with a clear spec and a way to check the result. Higher effort fixed missed edge cases but not a wrong approach, and it led the agent to make more assumptions on the human's behalf. Larger models at high effort paid off on long unsupervised runs and on edge-case-heavy work. ([Anthropic engineering: Match model and effort to scope, checkability and supervision](../principles/anthropic/match-model-and-effort-to-scope-checkability-and-supervision.md))

## Open hypotheses
- Small or local models only work reliably when a stronger model has planned the task first and it is scoped to named files. ([Birgitta Böckeler: Plan with strong models, execute narrow tasks with weaker ones](../principles/bockeler/plan-with-strong-models-execute-narrow-tasks-with-weaker-ones.md))
  - How to test it: Run local-model tasks with and without a plan from a frontier model and with and without named file scope. Compare success rate and engineer setup time against a frontier-model baseline.
- Storing wide, high-cardinality events instead of separate metrics, logs and traces lets agents debug production issues faster. ([Charity Majors: Keep telemetry wide and high-cardinality](../principles/majors/keep-telemetry-wide-and-high-cardinality.md))
  - How to test it: Give agents a set of real incidents to investigate under each telemetry setup. Time how long each takes to isolate the cause, and count how often a question needed new instrumentation.
