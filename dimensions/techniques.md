# Techniques

Concrete techniques for directing agents, such as prompting, task decomposition, context engineering and harness setup.

## Where the experts agree
- The codebase itself is the strongest context an agent gets. Clean abstractions, consistent vocabulary, house-style tests and working examples steer agent output more reliably than prose instructions, so investing in code structure is investing in agent performance. ([Unmesh Joshi: Well-designed code is the primary harness](../principles/joshi/well-designed-code-is-the-primary-harness.md), [Thoughtworks: Code structure is a running cost of agent work](../principles/thoughtworks/code-structure-is-a-running-cost-of-agent-work.md), [Simon Willison: The codebase, its examples and its instructions are agent context](../principles/willison/the-codebase-its-examples-and-its-instructions-are-agent-context.md), [Gergely Orosz: Steer agents with classic structure and organisational context](../principles/orosz/steer-agents-with-classic-structure-and-organisational-context.md))
- Team standards, conventions and tacit reviewer knowledge belong in version-controlled instruction files in the repository, reviewed like code and shared across every tool and team member. Knowledge that lives only in chat or in people's heads doesn't exist for the agent. ([Thoughtworks: Encode intent and standards in versioned artifacts](../principles/thoughtworks/encode-intent-and-standards-in-versioned-artifacts.md), [Steve Yegge: Version-controlled, layered agent instructions and workflow templates](../principles/yegge/version-controlled-layered-agent-instructions-and-workflow-templates.md), [OpenAI engineering: The repository is the agent's system of record](../principles/openai/the-repository-is-the-agent-s-system-of-record.md), [Anthropic engineering: Treat shared agent context as owned, pruned code](../principles/anthropic/treat-shared-agent-context-as-owned-pruned-code.md), [Addy Osmani: Encode team process as shared, tested skill workflows](../principles/osmani/encode-team-process-as-shared-tested-skill-workflows.md))
- Keep always-on context small. Start lean, add rules only when a failure you have actually seen calls for one, load longer procedures on demand, and prune guidance that newer models no longer need. ([Birgitta Böckeler: Grow agent context gradually](../principles/bockeler/grow-agent-context-gradually.md), [Addy Osmani: Keep agent context lean, hand-written and earned](../principles/osmani/keep-agent-context-lean-hand-written-and-earned.md), [Anthropic engineering: Treat shared agent context as owned, pruned code](../principles/anthropic/treat-shared-agent-context-as-owned-pruned-code.md), [Steve Yegge: Keep agent context lean and re-inject it automatically](../principles/yegge/keep-agent-context-lean-and-re-inject-it-automatically.md))
- Agent instructions need regression tests. Run evals with should-trigger cases, safe counterexamples and unrelated changes, test skill routing in CI, and re-run evals after model upgrades or pruning, because noisy guidance erodes trust. ([OpenAI engineering: Evaluate agent instructions like code](../principles/openai/evaluate-agent-instructions-like-code.md), [Addy Osmani: Encode team process as shared, tested skill workflows](../principles/osmani/encode-team-process-as-shared-tested-skill-workflows.md), [Anthropic engineering: Treat shared agent context as owned, pruned code](../principles/anthropic/treat-shared-agent-context-as-owned-pruned-code.md))
- Keep plans and work state as committed artifacts rather than in the session, so humans can review scope before building and a fresh session can pick up after a crash, compaction or handoff. ([Simon Willison: Plan in the repo, steer in flight, land small steps](../principles/willison/plan-in-the-repo-steer-in-flight-land-small-steps.md), [Steve Yegge: Keep agent work state in a durable work graph, not the session](../principles/yegge/keep-agent-work-state-in-a-durable-work-graph-not-the-session.md))

## Where they disagree
- **Should agent instructions be rigid, step-by-step procedures or light guidance that relies on the model's judgement and on examples in the code?**
  - Write skills as explicit workflows or graphs with exit criteria, mandatory completion steps and rebuttals to the excuses agents give for skipping steps, and state architectural constraints outright. ([Addy Osmani: Encode team process as shared, tested skill workflows](../principles/osmani/encode-team-process-as-shared-tested-skill-workflows.md), [Steve Yegge: Version-controlled, layered agent instructions and workflow templates](../principles/yegge/version-controlled-layered-agent-instructions-and-workflow-templates.md), [Kent Beck: Personas shape style; explicit constraints shape architecture](../principles/beck/personas-shape-style-explicit-constraints-shape-architecture.md))
  - Agents copy patterns in the code, so examples beat prose, and with frontier models instructions can lean on judgement rather than rigid rules. Workarounds should be stripped after each model upgrade. ([Simon Willison: The codebase, its examples and its instructions are agent context](../principles/willison/the-codebase-its-examples-and-its-instructions-are-agent-context.md), [Anthropic engineering: Treat shared agent context as owned, pruned code](../principles/anthropic/treat-shared-agent-context-as-owned-pruned-code.md))
  - Evidence to settle it: Run the same task set on the current frontier model with a rigid step-by-step skill, a short judgement-based instruction plus pointers to examples, and both together. Compare across two model generations.
  - Metric: Rate of skipped mandated steps, first-pass acceptance rate and tokens per task for each instruction style.
- **Should teams invest in carefully encoding expertise up front, or generate many cheap attempts and select the winners?**
  - Encode senior developers' tacit standards, specs and rules in versioned artifacts so output quality doesn't depend on who prompts. ([Thoughtworks: Encode intent and standards in versioned artifacts](../principles/thoughtworks/encode-intent-and-standards-in-versioned-artifacts.md), [OpenAI engineering: Encode reviewers' tribal knowledge as scoped agent review rules](../principles/openai/encode-reviewers-tribal-knowledge-as-scoped-agent-review-rules.md))
  - Following the Bitter Lesson, let many agents try different approaches, discard most of them and keep whatever ships at the lowest cost. This may beat hand-encoded expertise. ([Kent Beck: Try many cheap attempts and keep the winners](../principles/beck/try-many-cheap-attempts-and-keep-the-winners.md))
  - Evidence to settle it: On a set of comparable features, compare best-of-N attempts with minimal rules against a single attempt guided by fully encoded standards, including the cost of writing and maintaining the standards.
  - Metric: Total cost (tokens plus human hours) and elapsed time per accepted feature, and defects found after merge.

## Measured
- Thoughtworks measured a fixed change run by a fresh agent before and after refactoring a 17K-line file. Input tokens for the same change fell by 83%, so poor code structure is a recurring token cost. ([Thoughtworks: Code structure is a running cost of agent work](../principles/thoughtworks/code-structure-is-a-running-cost-of-agent-work.md))
- On OpenAI's review eval suite, which seeds known violations, agent reviewers given short, scoped review rules recovered 98% of required findings, against 58% for the baseline without rules. ([OpenAI engineering: Encode reviewers' tribal knowledge as scoped agent review rules](../principles/openai/encode-reviewers-tribal-knowledge-as-scoped-agent-review-rules.md))
- Context files that were generated or bloated lowered task success and raised token cost compared with lean, hand-written ones. Evals run after pruning workarounds and when models change show which instructions still earn their place. ([Addy Osmani: Keep agent context lean, hand-written and earned](../principles/osmani/keep-agent-context-lean-hand-written-and-earned.md), [Anthropic engineering: Treat shared agent context as owned, pruned code](../principles/anthropic/treat-shared-agent-context-as-owned-pruned-code.md))

## Open hypotheses
- Agents succeed more often when each change touches only one cohesive, moderately sized file. Success drops both for very large files and for changes that span several files. ([Kent Beck: Keep agent changes to one cohesive file](../principles/beck/keep-agent-changes-to-one-cohesive-file.md))
  - How to test it: Tag agent tasks by number of files touched and by size of the largest file, then compare first-attempt acceptance rates across the buckets.
- Having an LLM interview a human one question at a time produces context that is cheaper to prepare and needs no more rework than context a human writes by hand. This sits in tension with the advice that humans, not agents, should write context files. ([Martin Fowler: Let the LLM interview the human to build context](../principles/fowler/let-the-llm-interview-the-human-to-build-context.md), [Addy Osmani: Keep agent context lean, hand-written and earned](../principles/osmani/keep-agent-context-lean-hand-written-and-earned.md))
  - How to test it: For paired tasks, prepare context once by interview and once by hand. Compare preparation time and the rework the downstream agent output needs.
