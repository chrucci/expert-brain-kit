# Techniques

Concrete techniques for directing agents, such as prompting, task decomposition, context engineering and harness setup.

## Where the experts agree
- The codebase is the most important context an agent gets. Clean structure, stable abstractions, consistent vocabulary, tests and working examples steer agent output more reliably than prompts, and small cohesive files let the agent read only what a change needs. ([Unmesh Joshi: Well-designed code is the primary harness](../principles/joshi/well-designed-code-is-the-primary-harness.md), [Thoughtworks: Code structure is a running cost of agent work](../principles/thoughtworks/code-structure-is-a-running-cost-of-agent-work.md), [Simon Willison: The codebase, its examples and its instructions are agent context](../principles/willison/the-codebase-its-examples-and-its-instructions-are-agent-context.md), [Gergely Orosz: Steer agents with classic structure and organisational context](../principles/orosz/steer-agents-with-classic-structure-and-organisational-context.md), [Kent Beck: Keep agent changes to one cohesive file](../principles/beck/keep-agent-changes-to-one-cohesive-file.md))
- Team standards, conventions and intent that the code does not show belong in versioned instruction files, rules and skills kept in the repository and reviewed like code. Then output quality does not depend on who is prompting, and knowledge kept only in chat or in people's heads is invisible to the agent. ([Thoughtworks: Encode intent and standards in versioned artifacts](../principles/thoughtworks/encode-intent-and-standards-in-versioned-artifacts.md), [OpenAI engineering: The repository is the agent's system of record](../principles/openai/the-repository-is-the-agent-s-system-of-record.md), [Steve Yegge: Version-controlled, layered agent instructions and workflow templates](../principles/yegge/version-controlled-layered-agent-instructions-and-workflow-templates.md), [Anthropic engineering: Treat shared agent context as owned, pruned code](../principles/anthropic/treat-shared-agent-context-as-owned-pruned-code.md), [Addy Osmani: Encode team process as shared, tested skill workflows](../principles/osmani/encode-team-process-as-shared-tested-skill-workflows.md))
- Keep always-on context small. Add a rule only when a real failure shows it is needed, load longer procedures on demand, and remove guidance that newer models no longer need. ([Birgitta Böckeler: Grow agent context gradually](../principles/bockeler/grow-agent-context-gradually.md), [Addy Osmani: Keep agent context lean, hand-written and earned](../principles/osmani/keep-agent-context-lean-hand-written-and-earned.md), [Anthropic engineering: Treat shared agent context as owned, pruned code](../principles/anthropic/treat-shared-agent-context-as-owned-pruned-code.md), [Steve Yegge: Keep agent context lean and re-inject it automatically](../principles/yegge/keep-agent-context-lean-and-re-inject-it-automatically.md))
- Agent instructions need deterministic tests just as code does. Run small evals or CI checks that include cases that should trigger, safe counterexamples and unrelated changes, and narrow or remove guidance that creates noise. ([OpenAI engineering: Evaluate agent instructions like code](../principles/openai/evaluate-agent-instructions-like-code.md), [Addy Osmani: Encode team process as shared, tested skill workflows](../principles/osmani/encode-team-process-as-shared-tested-skill-workflows.md), [Anthropic engineering: Treat shared agent context as owned, pruned code](../principles/anthropic/treat-shared-agent-context-as-owned-pruned-code.md))

## Where they disagree
- **Should process be enforced through rigid step-by-step workflows, or left to model judgement guided by examples in the code?**
  - Write skills and templates as explicit workflows with exit criteria, mandatory completion steps and rebuttals for the excuses agents give for skipping steps. ([Addy Osmani: Encode team process as shared, tested skill workflows](../principles/osmani/encode-team-process-as-shared-tested-skill-workflows.md), [Steve Yegge: Version-controlled, layered agent instructions and workflow templates](../principles/yegge/version-controlled-layered-agent-instructions-and-workflow-templates.md))
  - Agents copy the patterns they find, so examples steer better than prose, and with frontier models instructions can rely on judgement rather than rigid rules. ([Simon Willison: The codebase, its examples and its instructions are agent context](../principles/willison/the-codebase-its-examples-and-its-instructions-are-agent-context.md))
  - Evidence to settle it: Run the same set of service changes with a rigid workflow skill and with a short judgement-based instruction plus reference examples, on the current frontier model, and compare skipped steps and convention adherence.
  - Metric: Share of agent tasks that skip a mandated step (tests, commit, handoff), and convention violations per accepted PR.
- **Is it better to put effort into one well-specified attempt or to run many cheap attempts and keep the best?**
  - Work is cheap, so try many approaches, throw most away and select the winners by cost. ([Kent Beck: Try many cheap attempts and keep the winners](../principles/beck/try-many-cheap-attempts-and-keep-the-winners.md))
  - Spend the effort up front on a concrete prompt or a reviewed committed plan, so the first attempt passes verification and no scope is quietly dropped. ([Andrej Karpathy: Write concrete prompts that state the goal](../principles/karpathy/write-concrete-prompts-that-state-the-goal.md), [Simon Willison: Plan in the repo, steer in flight, land small steps](../principles/willison/plan-in-the-repo-steer-in-flight-land-small-steps.md))
  - Evidence to settle it: For a batch of comparable tasks, compare best-of-N runs from a light prompt against a single run from a reviewed plan, counting total tokens, human minutes and dropped requirements.
  - Metric: Total cost (tokens plus human review minutes) per accepted change, and dropped requirements per task.

## Measured
- Thoughtworks measured that refactoring a 17K-line file cut input tokens for the same change by 83%. They benchmark this by having a fresh agent run a fixed change at each codebase checkpoint. ([Thoughtworks: Code structure is a running cost of agent work](../principles/thoughtworks/code-structure-is-a-running-cost-of-agent-work.md))
- On OpenAI's review eval suite, short review rules scoped to the code they govern raised recovery of required findings from 58% to 98% compared with a baseline reviewer. ([OpenAI engineering: Encode reviewers' tribal knowledge as scoped agent review rules](../principles/openai/encode-reviewers-tribal-knowledge-as-scoped-agent-review-rules.md))
- Generated or bloated context files lowered task success and raised token cost compared with lean hand-written ones. Removing outdated workarounds after a model upgrade and re-running evals is the check that pruning did no harm. ([Addy Osmani: Keep agent context lean, hand-written and earned](../principles/osmani/keep-agent-context-lean-hand-written-and-earned.md), [Anthropic engineering: Treat shared agent context as owned, pruned code](../principles/anthropic/treat-shared-agent-context-as-owned-pruned-code.md))

## Open hypotheses
- Giving each agent a command-line interface it can drive, plus a feature map, so it can start its own copy of the system, inspect state and read structured JSON back, makes end-to-end self-verification practical. For a services team this would mean a local harness that runs the service and its data flows. ([Lauren Tan: Give agents a drivable interface and feature map of the system](../principles/tan/give-agents-a-drivable-interface-and-feature-map-of-the-system.md))
  - How to test it: Build a drivable CLI for one service, then compare the post-merge defect rate of agent PRs verified through it with that of other agent PRs over a few weeks.
