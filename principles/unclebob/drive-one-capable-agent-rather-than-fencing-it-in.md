# Drive one capable agent rather than fencing it in

Verified: 2 verbatim quotes from 1 source

Dimension: Number of agents (agent-count)

Evidence: experience

How to measure: Compare output and rework for work done by driving a single agent directly against work done through a multi-agent or constraining harness.

After months building a restrictive harness, Martin found he did all the real work by driving a single agent that kept improving. He now treats a strong agent as a senior colleague to discuss designs with, not as a worker to be constrained. This is in tension with his role-pipeline swarm work.

## Quotes

> The real giveaway was that I never used the harness to create the harness. The whole time I was creating it, I was just driving a single agent, and the agent was getting better and better.
>
> [Uncle Bob: Why I Stopped Reading Code and Building Harnesses | Aviator](https://www.aviator.co/podcast/uncle-bob-martin-ai-clean-code)

> If I am willing to invest that much trust into a single agent, and give it that level of consideration, why am I putting it into a harness that makes it act like a menial slave?
>
> [Uncle Bob: Why I Stopped Reading Code and Building Harnesses | Aviator](https://www.aviator.co/podcast/uncle-bob-martin-ai-clean-code)
