# Use metrics for a team's own improvement, not as targets or rankings

Verified: 2 verbatim quotes from 1 source

Dimension: Metrics (metrics)

Evidence: opinion

How to measure: Check whether dashboards pair opposing measures, such as deployment frequency with change fail rate, and whether any metric is set as a mandated target.

Delivery metrics show whether a team is getting better over time. Mandated targets invite gaming and a single number can't describe a delivery system, so use several metrics that pull against each other.

## Quotes

> Teams should identify multiple metrics, including some with a healthy amount of tension between them.
>
> [DORA | DORA’s software delivery performance metrics](https://dora.dev/guides/dora-metrics/)

> making broad statements like, “Every application must deploy multiple times per day by year’s end,” increases the likelihood that teams will try to game the metrics.
>
> [DORA | DORA’s software delivery performance metrics](https://dora.dev/guides/dora-metrics/)
