# A small team with many agents needs large-organisation structure

Verified: 2 verbatim quotes from 1 source

Dimension: Number of people (team-size)

Evidence: experience

How to measure: Track merge collisions between engineers and meeting time spent sharing the current state as agent throughput per engineer rises.

When each engineer directs output equal to many people's, a team of about seven needs strict module boundaries so people don't collide, and deliberate synchronous knowledge sharing, such as a long daily standup, because no one can follow the state of the code alone.

## Quotes

> We have a daily standup that’s 45 minutes long because we almost have to. Fan out the understanding of the current state.
>
> [Extreme Harness Engineering for Token Billionaires: 1M LOC, 1B toks/day, 0% human code, 0% human review — Ryan Lopopolo, OpenAI Frontier & Symphony](https://latent.space/p/harness-eng)

> But if every person is actually like 10 to 50. Then the like numbers on being super, super deep into decomposition and sharding and like proper interface boundaries make a lot more sense.
>
> [Extreme Harness Engineering for Token Billionaires: 1M LOC, 1B toks/day, 0% human code, 0% human review — Ryan Lopopolo, OpenAI Frontier & Symphony](https://latent.space/p/harness-eng)
