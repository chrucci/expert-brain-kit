# Use in-place autocomplete as a precise spec for intricate code

Verified: 3 verbatim quotes from 1 source

Dimension: Techniques (techniques)

Evidence: experience

How to measure: Compare time to an accepted change and post-acceptance edits for autocomplete-driven versus prompt-driven work on the same kind of task.

On intricate or novel code, going to where the code belongs and typing the first few characters tells the model what you want faster than describing it in English. The human stays the architect and the model fills in the code.

## Quotes

> But you’re still very much the architect of what you’re writing.
>
> [Andrej Karpathy — AGI is still a decade away](https://www.dwarkesh.com/p/andrej-karpathy)

> If I just navigate to the part of the code that I want, and I go where I know the code has to appear and I start typing out the first few letters, autocomplete gets it and just gives you the code.
>
> [Andrej Karpathy — AGI is still a decade away](https://www.dwarkesh.com/p/andrej-karpathy)

> This is a very high information bandwidth to specify what you want.
>
> [Andrej Karpathy — AGI is still a decade away](https://www.dwarkesh.com/p/andrej-karpathy)
