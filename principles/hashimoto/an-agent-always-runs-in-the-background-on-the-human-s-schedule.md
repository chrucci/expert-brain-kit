# An agent always runs in the background, on the human's schedule

Verified: 4 verbatim quotes from 2 sources

Dimension: Roles for humans (human-roles)

Evidence: experience

How to measure: Compare engineers' uninterrupted focus time and throughput with agent notifications on and off, along with the share of hours that have an agent task running.

Each engineer keeps an agent busy on slow, low-thinking work such as planning, research or edge-case analysis while they do the thinking work. Notifications stay off so the human decides when to check in. Context switching is expensive, and background agents only pay off if the human's focus stays intact.

## Quotes

> Context switching is very expensive. In order to remain efficient, I found that it was my job as a human to be in control of when I interrupt the agent, not the other way around.
>
> [My AI Adoption Journey](https://mitchellh.com/writing/my-ai-adoption-journey)

> If I'm coding, I want an agent planning. If they're coding, I want to be reviewing. But there should always be an agent doing something.
>
> [Mitchell Hashimoto’s new way of writing code at 01:19:22](https://newsletter.pragmaticengineer.com/p/mitchell-hashimoto?t=4762s)

> I choose when I interrupt the agent. It doesn't get to interrupt me.
>
> [Mitchell Hashimoto’s new way of writing code at 01:45:47](https://newsletter.pragmaticengineer.com/p/mitchell-hashimoto?t=6347s)

> I try to identify the tasks that don't require thinking and the tasks that do require thinking and just delegate.
>
> [Mitchell Hashimoto’s new way of writing code at 01:45:47](https://newsletter.pragmaticengineer.com/p/mitchell-hashimoto?t=6347s)
