# Run one or two agents, not a swarm

Verified: 4 verbatim quotes from 2 sources

Dimension: Number of agents (agent-count)

Evidence: experience

How to measure: Compare the human time spent fixing agent output and the acceptance rate per merged change when engineers run one, two or more agents at once.

Hashimoto usually runs a single background agent and at most two at once: a second agent is for research, or to compete with the first on a hard task. Every extra agent adds cleanup work for the human. The real limit is a steady supply of work worth delegating, not how many agents are running.

> I find having the one agent running is a good balance for me right now
>
> [My AI Adoption Journey](https://mitchellh.com/writing/my-ai-adoption-journey)

> I don't want to run agents for the sake of running agents.

> I don't find it that fun to clean their stuff up but periodically I'll run two in competition with each other because it's a harder task and I don't have a high confidence that they're going to just like crush it.
>
> [Mitchell Hashimoto’s new way of writing code at 01:19:54](https://newsletter.pragmaticengineer.com/p/mitchell-hashimoto?t=4794s)
