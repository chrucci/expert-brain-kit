# Match review depth to the stakes of the code

Verified: 2 verbatim quotes from 1 source

Dimension: Processes (processes)

Evidence: experience

How to measure: Sort changes into risk tiers and compare escaped defects and review hours for each tier.

Code for a long-lived product gets a full human review. Short-lived, low-risk code with no secrets or network access is judged only by whether it behaves correctly. Setting review effort by risk keeps human attention on the code that matters.
