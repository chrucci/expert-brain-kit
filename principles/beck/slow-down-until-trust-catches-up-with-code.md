# Slow down until trust catches up with code

Verified: 6 verbatim quotes from 1 source

Dimension: Processes (processes)

Evidence: opinion

How to measure: Track escaped defects, rollbacks and rework against merged code volume, alongside test coverage and integration batch size.

Agents let a team produce code faster than it builds trust, and that gap will correct painfully. Slow down so the code really works, and lean on trust-building practices such as thorough automated tests, small safe integrations, continuous deployment and alerting, because trustworthy software is the route to going faster.

## Quotes

> Slow development to ensure that the damn stuff actually works.
>
> [Trust Factory](https://newsletter.kentbeck.com/p/trust-factory)

> I’m saying trustworthy behavior resulting in trustworthy software resulting in trust is the path to effective augmented development.
>
> [Trust Factory](https://newsletter.kentbeck.com/p/trust-factory)

> That’s how you go faster. More chances to build trust->more focus on trustworthiness->more trust.
>
> [Trust Factory](https://newsletter.kentbeck.com/p/trust-factory)

> Thorough automated testing demonstrates trustworthiness to the rest of the team. It also builds trust within the programmer.
>
> [Trust Factory](https://newsletter.kentbeck.com/p/trust-factory)

> Continuous integration. Integrating small sets of changes, optimized for safety, reduces gotcha moments for the rest of the team.
>
> [Trust Factory](https://newsletter.kentbeck.com/p/trust-factory)

> What I notice about this list that I didn’t expect is that each practice that creates trust also encourages trustworthiness.
>
> [Trust Factory](https://newsletter.kentbeck.com/p/trust-factory)
