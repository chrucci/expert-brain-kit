# Each engineer finds their own agent count from data

Verified: 2 verbatim quotes from 1 source

Dimension: Number of agents (agent-count)

Evidence: opinion

How to measure: For each engineer, compare merged changes, change failure rate and cycle time across periods spent running different numbers of concurrent agents.

There is no single right number of concurrent agents for a whole team, because technical limits and cognitive styles differ. Each engineer should experiment and collect data to find the number of agents at which they deliver the most impact.

## Quotes

> Everyone should put in the time and experimentation to find out where their "sweet spot" is.
>
> [AI Norms & Values, Part 2 of 3: AI for Honeycomb Engineering](https://www.honeycomb.io/blog/ai-norms-values-part-2-ai-honeycomb-engineering)

> Ultimately, the answer to this question is you should run the number of agents that allows you to deliver impact most effectively, and you should do the work of generating the data to answer that question for yourself.
>
> [AI Norms & Values, Part 2 of 3: AI for Honeycomb Engineering](https://www.honeycomb.io/blog/ai-norms-values-part-2-ai-honeycomb-engineering)
