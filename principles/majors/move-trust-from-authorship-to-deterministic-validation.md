# Move trust from authorship to deterministic validation

Verified: 3 verbatim quotes from 1 source

Dimension: Deterministic guardrails (deterministic-guardrails)

Evidence: opinion

How to measure: Track the share of agent-written changes that ship unread but pass validation suites, against the escaped-defect and incident rate for those changes.

When nobody reads the code agents write, the trust that used to come from writing it has to be rebuilt elsewhere: in tests, evals, conformance suites and constrained pathways for the model. Without that, cheap non-deterministic generation wears away the system's foundations.

## Quotes

> If you're debiting from this trust account and the creation of the code, it has to get built up somewhere else.
>
> [Stop being skeptical about AI for development with Charity Majors at 00:27:13](https://newsletter.pragmaticengineer.com/p/stop-being-skeptical-about-ai-for?t=1633s)

> We have to learn how to give it carved pathways and places where we kind of corral it, where we use it in the way that it's a superpower and not in the way that like erodes our foundations.
>
> [Stop being skeptical about AI for development with Charity Majors at 00:28:03](https://newsletter.pragmaticengineer.com/p/stop-being-skeptical-about-ai-for?t=1683s)

> we're going to need a lot of evals. We're going to need a lot of tests. But the generation is so cheap that it really, I think it forces us in that direction.
>
> [Stop being skeptical about AI for development with Charity Majors at 00:14:17](https://newsletter.pragmaticengineer.com/p/stop-being-skeptical-about-ai-for?t=857s)
